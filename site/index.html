System Architecture

Multi-Stage Research & Verification Pipeline

STAGE 01 • RETRIEVAL
Source Discovery & Firecrawl Fetch
Navigates candidate developer documentation URLs, crawls official API references, authentication guides, and pricing pages using Firecrawl with direct HTTP fallback and SHA-256 caching.
STAGE 02 • SYNTHESIS
OpenAI Extraction & Evidence Quoting
OpenAI generative model extracts factual integration candidate claims and pairs every candidate field with verbatim quoted passages, exact source URLs, and fetch timestamps.
STAGE 03 • DECISIONS
TypeSafe Jev Atomic Verification
Dispatches atomic Noul (binary) and Choice decision queries to TypeSafe Jev (typesafe/jev-1.13) to mathematically verify quoted excerpts against candidate claims without hallucinations.
STAGE 04 • COMPOSITION
Code-Owned Deterministic Rules
Python code owns the business logic for calculating api_breadth and final buildability status based on confirmed credential access conditions, eliminating arbitrary LLM guessing.
STAGE 05 • VALIDATION
Deterministic Schema & Evidence Audit
Validates 100% of generated records against strict Pydantic schemas, verifies verbatim quote matching against retrieved markdown snapshots, and ensures zero logical contradictions.
STAGE 06 • PUBLISHING
Static Compilation & Web Deployment
Aggregates cross-category statistics, generates zero-CORS client bundles, exports CSV datasets, and deploys this responsive, interactive case study page to Vercel.

Runnable CLI Triggers & Execution Commands

The entire research pipeline is 100% reproducible via standard Python CLI commands. Checkpoint resumption ensures interrupted runs can seamlessly resume.

# 1. Investigate a single application by ID (e.g. #1 Salesforce)
$ python -m src.research --app-id 1
# 2. Run or resume the complete 90-app automated research agent
$ python -m src.research --all --resume
# 3. Deterministically validate schemas, quotes, and rule consistency
$ python -m src.validate
# 4. Run reproducible human-in-the-loop stratified audit
$ python -m src.audit
# 5. Compile static analytics and regenerate frontend datasets
$ python -m src.analyze
Transparency & Disclosures

Scope Discrepancy & System Limitations

Assignment Scope Discrepancy Disclosure

The PDF assignment prompt specifies: “You will evaluate 100 apps across 10 categories”. However, the itemized table provided in the take-home document lists only 90 applications across 9 categories, terminating abruptly at #90 PitchBook in Category 9 (Finance and Fintech).

In accordance with engineering integrity principles, no placeholder entries were fabricated. The pipeline rigorously analyzes all 90 provided entries and transparently reports coverage as 90/90 (100% of provided dataset). Should Category 10 (#91–#100) become available, appending it to data/apps.json will immediately process the new apps upon running python -m src.research --all --resume.

Research Agent Limitations & Boundary Conditions

  • Anti-Bot & Cloudflare Challenges: Certain developer portals deploy aggressive JS challenges that block direct HTTP scraping; Firecrawl and browser emulation were used to circumvent these blocks.
  • Login-Walled Developer Consoles: Platforms like Gladly and PitchBook conceal developer token creation behind enterprise subscription logins; public marketing docs were utilized for evidence.
  • Unambiguous Evidence Standard: When documentation lacks explicit confirmation of self-serve credentials, the pipeline conservatively classifies the platform as conditional or outreach_needed rather than hallucinating ease of access.
